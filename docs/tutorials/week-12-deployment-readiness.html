第 12 周：从本地原型到可上线——部署就绪路线与云服务器部署

同学生产化Docker云部署

第 11 周已用选定配置（bge-m3 + deepseek-v4-flash）跑通端到端 RAG demo。这一周回答两个问题：这个项目还差什么才能「上线」，以及能不能部署在云服务器。

一、先说结论：能上云，但当前还不能直接当生产系统用

项目的技术内核是成熟可部署的：FastAPI（ASGI）+ SQLite + 真实 embedding/LLM 客户端 + 可续跑缓存 + 65 个测试。它完全可以打包成 Docker 镜像跑在任意云服务器（阿里云 ECS / 腾讯云 CVM / 轻量应用服务器 / 海外 VPS / Render·Railway 等 PaaS）。

但「能跑起来」≠「能上线」。当前状态是一个本地原型 + 评测脚本集合：没有前端、没有鉴权、没有并发向量库、没有生产级服务进程、没有可观测性、没有 CI/CD。要面向真实用户，需要补齐下面八块。下面按优先级排序——P0 是上线前必须有，P1 是上线后很快要补，P2 是规模化才需要。

二、部署就绪清单（按优先级）

P0 · 上线前必须有

能力当前要做什么
生产服务进程开发服务器 uvicorn 单进程用 gunicorn -k uvicorn.workers.UvicornWorker -w N 起多 worker；N≈CPU 核数；前面可加 Nginx 反代
容器化无写 Dockerfile（python:3.11-slim + pip install -e .），镜像不含 .env
密钥管理.env 本地云端用环境变量 / Secret Manager；密钥永远不进镜像、不进 Git
向量存储内存里按 cache 文件加载接入真正向量库（pgvector / Qdrant / Milvus），预embed语料一次后常驻；当前「每次启动重算」不支持并发与持久
接口鉴权无加 API Key / JWT；未带 token 返回 401；这是对外开放前的硬门槛
输入防护有基础校验加请求体大小上限、速率限制（slowapi/redis）、CORS 白名单

P1 · 上线后很快要补

能力说明
前端/产品界面FastAPI 只有 /docs。需一个最小聊天 UI（静态页或 Streamlit/Gradio），否则用户没法用
可观测性结构化日志 + 基础指标（QPS、延迟、embedding/LLM 错误率）+ 错误告警
数据库持久化SQLite 在云上 ephemeral 磁盘会丢；挂云盘或换托管 Postgres（同一实例可先用云盘挂载）
成本护栏embedding/LLM 按量计费；加每日预算上限、单用户配额、失败计入成本看板
CI/CDGitHub Actions：push 跑 pytest → 构建镜像 → 部署；测试不绿禁止发布

P2 · 规模化才需要

  • 自托管 embedding：bge-m3 是开源模型，高并发/高成本场景下用 GPU 自建 embedding 服务（如 TEI / vLLM），省去每 Query 的远程调用与出网流量。
  • 多模型 fallback：LLM 接火山 deepseek-v4-flash 为主，硅基 DeepSeek-V3.2 为备，一家抖动自动切换。
  • 缓存层：热门问题答案缓存（Redis），降延迟降成本。
  • 水平扩展：无状态 API + 托管向量库 + 对象存储语料，多副本横向扩容。

三、云服务器部署最小路径（真能跑起来的那种）

下面是一条「先跑通、再加固」的最小可行路线。每一步都可独立验证。
1
准备服务器：买一台云服务器（2 vCPU / 4 GB 起；RAG 主要吃出站 API，不吃本机算力，配置可很低）。系统 Ubuntu 22.04。开放 80/443 与 SSH 端口。
2
出网连通性：确保服务器能访问火山方舟 / 硅基流动 API（curl https://api.siliconflow.cn/v1/models 能通）。注意：我们本地沙箱之前被代理挡住外部域名，云服务器上要确认没有公司代理 / 防火墙拦截 egress，否则 embedding/LLM 会全部失败。
3
加 Dockerfile：基于 python:3.11-slim，pip install -e .，CMD ["gunicorn", ...]。镜像构建时不复制 .env。
4
注入密钥：docker run -e EMBEDDING_API_KEY=... -e LLM_API_KEY=... -e ... 或 docker secret / compose env_file（env_file 不进镜像、不进 Git）。
5
预构建向量：在服务器上跑一次 scripts/run_rag_demo.py --docs 全量 或专门的 build_index 脚本，把语料 embed 进向量库（Qdrant/pgvector），之后检索不再逐次 embed 全库。
6
起服务 + 反代：docker compose up 起 API；Nginx 反代 / → 127.0.0.1:8000，配 HTTPS（Let's Encrypt / certbot）。
7
加鉴权与限流：在 API 层加 API Key 中间件 + 速率限制，再对外开放。
8
CI/CD：GitHub Actions 测试绿 → 构建推送镜像 → 服务器拉新镜像重启。

最小 Dockerfile 骨架

# Dockerfile
FROM python:3.11-slim
WORKDIR /app
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt
COPY . .
RUN pip install --no-cache-dir -e .
# 密钥从运行时环境变量注入，绝不 COPY .env
CMD ["gunicorn", "paper_api:create_app()", \
     "-k", "uvicorn.workers.UvicornWorker", "-w", "2", "-b", "0.0.0.0:8000"]
成本提示：RAG 的 embedding/LLM 走第三方 API 按量计费，本机只需一台小规格服务器跑 API + 向量库。若语料固定、问答量不大，月成本主要是 API 调用费，服务器本身很低（轻量应用服务器约几十元/月）。

四、当前架构离生产还差的关键一件：向量存储

这是最容易被忽略、却最决定「能不能服务真实用户」的一点。现在检索索引是进程内按 cache 文件加载，每次启动要把 13976 个 chunk 重新 embed 一遍（且依赖外部 API 稳定）。这不支持：并发用户、索引热更新、故障后秒级恢复。

最小改动：把 chunk_corpus 的向量写入 pgvector（和现有 SQLite 同机先跑通），检索改成 SELECT ... ORDER BY embedding <=> %s LIMIT 10。这样语料只需 embed 一次，之后全是本地向量检索，延迟和成本都可控，也顺手把「每次启动重算」这个脆弱点去掉。

五、给简历用的「上线」叙事

不要等全部做完才写进简历。可以这样表述（已是事实）：

  • 已交付：RAG 阅读助手，bge-m3 召回 + deepseek-v4-flash 生成，chunk 级真实 QA 基准，可续跑缓存，65 单测，端到端 demo 跑通。
  • 可讲亮点：多模型注册表与可达性过滤、可续跑原子缓存（抗 Windows 文件锁 + API 抖动）、reranker 增益的受控消融、配置收敛决策。
  • 路线图（诚实）：向量库持久化（pgvector）、Docker + gunicorn 生产进程、API 鉴权与限流、前端 UI、CI/CD——即本节 P0/P1 清单，正在推进。
面试时「我清楚它离生产还差什么、以及为什么」比「我号称做完了」更有分量。本节清单就是你回答「如何达到上线水平」的框架。

六、下一步建议（落地顺序）

  1. 向量库持久化（pgvector）：去掉「每次启动重算」，这是上生产的第一块基石。
  2. Dockerfile + gunicorn：本地就能 docker build && docker run 验证镜像。
  3. 最小前端：一个能发问题、显示答案+citation 的静态页，产品闭环 visibly 完成。
  4. 鉴权 + 限流：对外开放前的硬门槛。
  5. 买一台轻量云服务器，按第三节 8 步部署：你就有了一个真正「上线」的 RAG 服务。

补充：本项目所有外部模型调用都走标准 OpenAI 兼容协议，迁移到自托管或换厂商只需改注册表与 .env，业务代码不动——这是前几周抽象（协议 + 注册表）的直接回报。
