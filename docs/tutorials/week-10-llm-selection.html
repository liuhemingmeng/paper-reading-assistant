第 10 周：接入真实 LLM（RAG 答案生成）并清理 reranker

同学RAG 生产闭环多模型选型

把 RAG 从「离线 Fake」推进到「真实 LLM 回答」，并从 reranker 列表永久移除视觉语言模型 Qwen/Qwen3-VL-Reranker-8B。

一、任务背景

你提供了 5 个候选 LLM（火山 3 个 + 硅基 2 个），要求从中选合适的接入 RAG 答案生成与阅读洞察；同时明确要求不再使用 Qwen/Qwen3-VL-Reranker-8B。

本阶段目标：① 联网验证这批模型到底哪些可用；② 选一个作为默认 RAG LLM 并落配置；③ 把 LLM 纳入既有的「模型注册表」范式（与 embedding / reranker 一致），便于后续多模型对比；④ 干净地移除 VL reranker。

为什么沿用注册表范式？第 9 周已经把 embedding / reranker 做成「短名 → 客户端」的注册表 + smoke 可达过滤。LLM 是同一条路：smoke_llms.py 记录可达性，get_reachable_llm_specs() 自动跳过不可达模型，代码与密钥彻底解耦。

二、候选清单与联网 smoke

scripts/smoke_llms.py 对每个候选发一个中文学术 prompt（解释 RAG 为何减少幻觉），确认密钥有效、chat/completions 可用，并记录延迟与响应片段。密钥只从环境变量读、不落盘。

三、glm-4-7-251222 为什么 404？

我没有把 404 当成「模型名写错」就略过，而是拉了火山方舟模型目录核对：glm-4-7-251222确实在目录里——名字完全正确。它返回 InvalidEndpointOrModel.NotFound，和第 9 周 volcano-large-text-250515 是同一类问题：模型存在，但当前 key 没给它开通推理权限。

这类 404 只能由账号侧解决（在火山控制台给该模型开通 / 创建推理接入点）。代码无需改动——它已登记进注册表，等 scripts/smoke_llms.py 复测返回 ok 后，get_reachable_llm_specs() 会自动把它纳入可选列表。

六、移除 Qwen/Qwen3-VL-Reranker-8B

为什么移除

它是视觉语言（VL）reranker。第 9 周基准已暴露：在纯文本检索上，VL embedding（qwen3vl-embed-8b）R@1 暴跌到 0.241（arXiv）；对应的 VL reranker 接在纯文本检索器上增益同样不具代表性，且它本就不是为纯文本检索设计的。项目语料是纯文本论文 / 行业文档，保留它会浪费调用、干扰结论。

改了什么

  • model_registry.py：从 get_reranker_specs() 删除该 spec（加注释说明原因）。
  • 清理 data/rerank_cache/ 中该 reranker 的 7 个组合缓存文件。
  • scripts/benchmark_retrieval.py 无需改动——它用 get_reachable_reranker_specs() 自动跟随。

现在 reranker 仅剩 2 个纯文本模型：qwen3-rerank-4b / qwen3-rerank-0.6b。

八、局限与下一步

本阶段局限：smoke 只验证了「模型可达 + 中文响应质量 OK」，还没做端到端 RAG 答案质量基准。smoke 的 prompt 是开放式问答，不是「基于给定证据回答」，所以不能直接证明它在真实 RAG 管线里的忠实度。

下一步（生产级闭环，按优先级）：

  1. 真实 LLM 答案质量：接入真实 LLM_* 后，用 scripts/evaluate_answers.py --faithfulness 跑答案质量闭环（忠实度裁判），呼应第 7 周设计。
  2. reranker 主场验证：构造「自然语言问题 → 证据段落」真实问答对重跑基准——这才是 reranker 增益的验证场（已知项检索低估其价值）。
  3. 多 LLM 对比：用新加的 LLM 注册表，对同一个证据集对比 4 个可达 LLM 的回答质量 / 延迟 / 成本，形成可写进简历的「模型选型报告」。

离线 Fake 链路仍保证每次提交都能回归检索命中与引用正确性，不依赖任何外部凭据；真实 key 只在运行时通过 .env 注入。
