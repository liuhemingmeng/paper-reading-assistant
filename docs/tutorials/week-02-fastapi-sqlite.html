2. HTTP 与 REST：先理解接口契约

后端 API 是一种协议：客户端按约定发送方法、路径、查询参数和 JSON 请求体；服务端返回状态码和 JSON 响应。无论前端是 React、命令行还是其他服务，只要遵守契约，就能调用后端。

方法与路径含义成功响应失败情况
POST /papers创建论文201 + 新对象422：字段缺失或非法
GET /papers分页列出论文200 + 数组422：分页参数越界
GET /papers/1读取 ID=1200 + 对象404：不存在
PATCH /papers/1局部更新200 + 更新对象404 / 422
DELETE /papers/1删除204，无响应体404

状态码是接口的一部分。201 表示“资源已创建”，204 表示“操作成功但没有内容返回”，404 表示“目标资源不存在”，422 表示“请求格式合法但字段不符合模型规则”。面试时能解释这些比背路由更重要。

3. 五层结构：为什么不把所有逻辑写进路由

src/paper_api/
├── api.py        # HTTP 路由、状态码、依赖注入
├── schemas.py    # Pydantic 输入/输出模型
├── models.py     # SQLAlchemy 表模型
├── database.py   # Engine、Session、建表
├── services.py   # CRUD 业务逻辑
└── __main__.py   # 启动 Uvicorn
HTTP 层：FastAPI 将请求 JSON 解析为 PaperCreate。
业务层：services.py 执行创建、查询、更新、删除。
存储层：SQLAlchemy 将 Paper 对象映射到 SQLite 的 papers 表。
响应层：PaperRead 过滤并序列化响应。

分层的直接价值是可替换。以后从 SQLite 切换 PostgreSQL，通常主要动数据库配置；从 REST 换成任务队列，核心 CRUD 服务仍可复用；测试既可测 HTTP，也可直接测服务函数。

4. FastAPI：路由与依赖注入

4.1 应用工厂

def create_app(database_url: str = DEFAULT_DATABASE_URL) -> FastAPI:
    engine = create_engine_for_url(database_url)
    session_factory = create_session_factory(engine)
    create_tables(engine)
    app = FastAPI(title="Paper Reading Assistant API")
    return app

create_app() 不只是“创建一个 app”。它接收数据库 URL，因此生产环境可使用 sqlite:///data/papers.db，测试可使用 sqlite://。这使环境差异成为参数，而不是散落在全局变量或 if/else 中。

4.2 依赖注入 Depends

@app.post("/papers", response_model=PaperRead, status_code=201)
def create_paper_route(data: PaperCreate, session: Session = Depends(get_db_session)):
    return create_paper(session, data)

FastAPI 看到 Depends(get_db_session) 后，会在每个请求开始时创建 Session，在请求结束后关闭 Session。路由不自己打开/关闭连接，也不需要知道 Session 工厂如何配置。这就是依赖注入：由框架在边界处提供所需资源。

与第 1 周的对应关系

argparse 把终端字符串转成 args；FastAPI 把 HTTP 请求转成函数参数。两者都是“输入边界校验”，只是协议不同。

5. Pydantic：请求和响应都要有模型

PaperCreate 是创建时允许客户端提交的字段，PaperUpdate 是局部更新字段，PaperRead 是服务端返回的字段。不要直接把 ORM 表模型同时作为外部请求模型，否则客户端可能传入不应控制的 id、时间戳等字段。

class PaperCreate(BaseModel):
    title: str = Field(min_length=1, max_length=300)
    authors: str = Field(min_length=1, max_length=500)
    abstract: str = Field(min_length=1, max_length=10_000)
    file_path: str | None = Field(default=None, max_length=1000)

Field 描述字段契约。FastAPI 据此生成 OpenAPI 文档、解析请求并在不合法时返回 422。field_validator 再处理“看起来满足长度但其实全是空格”的情况：

@field_validator("title", "authors", "abstract")
@classmethod
def strip_required_text(cls, value: str) -> str:
    value = value.strip()
    if not value:
        raise ValueError("must not be blank")
    return value

PaperRead 的 ConfigDict(from_attributes=True) 允许它从 SQLAlchemy 对象读取属性。响应模型还具有安全作用：即使 ORM 未来加了内部字段，只要 PaperRead 未声明，FastAPI 不会自动暴露它。

6. SQLAlchemy 与 SQLite：对象怎样变成表

6.1 三个概念不能混淆

概念本项目对应职责
Enginecreate_engine(...)连接数据库的底层配置和连接池
Sessionsession_factory()一次工作单元：查询、添加、提交、回滚
ORM Modelclass Paper(Base)Python 类到数据库表的映射
class Paper(Base):
    __tablename__ = "papers"
    id: Mapped[int] = mapped_column(Integer, primary_key=True)
    title: Mapped[str] = mapped_column(String(300), nullable=False)
    abstract: Mapped[str] = mapped_column(Text, nullable=False)

Mapped[str] 是类型注解，mapped_column(...) 既描述 Python 属性，也描述 SQL 列。Base.metadata.create_all() 会根据模型创建缺失表，但不会为生产级结构变更做迁移；后续项目复杂后应学习 Alembic。

6.2 为什么选择 SQLite？

SQLite 是一个文件，不需要启动数据库服务，适合本地单用户学习、原型与小型工具。缺点是并发写入能力有限，不适合多实例生产部署。第 2 周的目标是理解关系数据库和 ORM，不是提前引入运维复杂度。

测试的特殊配置

测试使用 sqlite://（内存数据库）和 StaticPool。内存 SQLite 通常每个连接各自独立，测试客户端可能跨线程/连接；StaticPool 强制复用同一连接，check_same_thread=False 则允许测试线程访问它。没有这两个设置，常见报错是“表不存在”，即使刚刚执行过建表。

7. CRUD：从请求到数据库的完整过程

7.1 创建

def create_paper(session: Session, data: PaperCreate) -> Paper:
    paper = Paper(**data.model_dump())
    session.add(paper)
    session.commit()
    session.refresh(paper)
    return paper
  • model_dump()：Pydantic v2 将已校验的数据转为字典。
  • session.add()：将对象加入当前工作单元，尚未真正写库。
  • commit()：提交事务，SQLite 生成主键和默认时间。
  • refresh()：从数据库重新加载对象，确保 id、时间戳等自动字段是最新值。

7.2 查询与分页

statement = select(Paper).order_by(Paper.id.desc()).offset(offset).limit(limit)
return list(session.scalars(statement))

不加分页的列表接口会随着数据增长越来越慢。这里允许 offset 为 0 以上，limit 限制为 1-100。真实高流量系统还会讨论 cursor pagination，但 offset/limit 是学习 CRUD 的正确起点。

7.3 更新：为什么用 exclude_unset=True

for field, value in data.model_dump(exclude_unset=True).items():
    setattr(paper, field, value)

PATCH 只更新用户实际发送的字段。若客户端只发送标题，作者和摘要必须保持原值。exclude_unset=True 区分“未发送”与“显式发送 null”，这也是为什么 file_path 可以被显式清空。

7.4 404 应在什么层生成？

services.py 抛出不包含 HTTP 细节的 PaperNotFoundError；api.py 捕获它并转成 HTTPException(404)。服务层因此能复用于命令行、定时任务或未来的 Agent 工具，而不被 Web 框架绑死。

8. 接口测试：为什么不只手工点 /docs

TestClient 让测试像 HTTP 客户端一样调用 API，但不需要真的启动 Uvicorn 和占用端口。每个测试函数通过 fixture 获取一个干净的内存数据库。

@pytest.fixture
def client() -> Generator[TestClient, None, None]:
    with TestClient(create_app("sqlite://")) as test_client:
        yield test_client
测试证明了什么
health应用能构造并响应健康检查
create + get请求校验、写库、自动 ID、读取链路正确
pagination排序、offset、limit 语义正确
updatePATCH 可局部修改并能显式清空可选字段
delete204 响应无 body，后续查询 404
404/422错误不是未处理 500，而是稳定的 API 契约
python -m pytest -q

本周最终结果为 17 passed。其中来自 FastAPI/Starlette 依赖的 TestClient 有一条弃用警告，不影响当前行为；后续升级依赖时需要检查框架推荐的测试客户端迁移方式。

10. 本周遇到的工程问题与常见坑

虚拟环境损坏

一次可编辑安装中断后，旧 .venv 的 pip 入口不可用。正确恢复方式通常是重建虚拟环境并从依赖文件重装。本次为避免清理保护触发大规模删除，临时新建 .venv-clean 完成验证；两者均已被 Git 忽略。日常开发建议只保留一个健康的 .venv。

不要把 data/papers.db 提交进仓库

它是本地运行数据，包含可变状态。代码和迁移/建表逻辑应被提交；个人论文、测试残留、数据库文件不应进入 Git。若将来需要演示数据，应写独立 seed 脚本或提交脱敏 JSON fixture。

不要把 SQL 写在路由里

把 session.execute(...)、事务提交和错误转换堆到路由里，短期能跑，后期无法测、无法复用。当前服务层虽然小，但这是后续 PDF 处理、RAG 索引任务和 Agent 工具都能继续沿用的边界。

11. 你应独立完成的练习

每个练习遵循同一流程：先写接口契约和测试预期，再实现 Pydantic 模型/服务/路由，最后运行完整测试。先自己写 20 分钟；卡住后再对照现有模块逐层排查。

  • 给 Paper 增加 year: int | None，限制为 1900 到当前年份。同步修改 ORM、创建/更新/响应模型、测试和 README。
  • 给 GET /papers 增加可选 keyword 参数，只按标题模糊匹配。考虑空白 keyword 与大小写。
  • 为 PATCH /papers/{id} 增加“空请求体”校验：没有任何字段时返回 422，而不是无意义地提交事务。
  • 写一个 scripts/seed_papers.py，通过 API 或服务层插入三条脱敏演示论文；不要把生成的 SQLite 文件提交。
  • 为数据库异常增加 rollback 保护，并写一个能模拟失败的服务层测试。
